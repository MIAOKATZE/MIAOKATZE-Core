# 迁移与多仓协作

## 0.1.23 候选：显式共享工作准入

新增 [`api.work.WorkGovernor`](work-governor.md)，将通用 CPU 许可、字节租约、有界 singleflight 和退休回收下沉 Core。Core 不拥有 GTMB 的生命周期、蓝图 schema、World/TE、付款、网络协议、具体 worker 或 GUI。GTMB 的 `HologramProcessGovernor` 保留全部既有公开方法与嵌套类型，作为 owner guard、配置和 metrics 的适配层。

采用新入口的 GTMB 将最低依赖与精确首次下载请求更新到 0.1.23；仍只调用旧 API 的系列 Mod 保留各自当前版本声明。已公开的 0.1.x 类型和方法未删除或改签名。进程共享配置由显式首个消费者固定，其他消费者复用同一实例；不要在 client/server 或不同 executor 内另建独立“全局”许可。

本节描述本次候选，不覆盖下面各历史阶段的版本与验收记录。正式 Core/消费者产物分别提交、发布和关联 PR，构建顺序为 Core 候选检查与固定产物，再构建 GTMB；组件通过不替代实际游戏负载验收。

本批 API 基线 0.1.3；七仓统一 Forge 区间 [0.1.3,0.2.0)。运行平台统一为 GTNH 2.9.0 RC2，GT 5.09.54.205、MUI2 2.3.92-1.7.10、GTNHlib 0.11.52；不再维护旧整合包 API 分派。消费者分别建立 task worktree 和版本 PR，原工作副本保留原分支及改动。Core 本轮经授权直接提交、打 Tag、推送；消费者 Tag 留在本地，直到各自 PR 合并后调整到最终合并提交，再重新构建、推正式 Tag 与 Release。不要将候选 Jar 当成已发布产品。

## 分工边界

Core 拥有基础设施与显式扩展点。每仓拥有维度与 Provider 注册、ID、权限门禁、场景、断言、业务对象与存档。TestKit 通过无全局副作用的时间预算设施复用；未来 runner、报告及 fixture 逐项采用组合式接口。不得让测试维度随 Core 安装自动开启。

## 后续迁移准入

1. 堆叠结构：组合式 base/stack/cap 布局与偏移设施；保留原 StructureLib 检查顺序，以及试探失败后重放检查的 hatch/errors 副作用。
2. 枢纽：缓存/失效/重试策略可以下沉，节点注册、跨维度权限、NBT 与有类型的公开字段保留原仓，不用泛型擦除悄悄改变 ABI。
3. 渲染系统：先拆几何、状态与资源；GTMB 继续拥有完整蓝图预览协议。专属模型、音效、视觉设计不作为基础库资源强行迁移。
4. 最小兼容：仅保留可选 Mod 是否存在、侧别隔离和真实 API 所需的薄接入点；日常不可用提示使用 debug。禁止重新引入旧 GT/AE 多版本探测、反射分派或按旧包降级的路径。存档迁移、物品 NBT 及 Core 公开 API 的兼容责任继续保留。
5. UI：逐项建立可注入颜色/材质与清晰状态所有权的组件，保持现有行为；不能把两个外观相似的 UI 当作同一架构。

## 版本与验证

先完成 Core 检查并固定不可变产物，再构建消费者。每个 PR 记录 Core 版本、源码提交、Tag、干净构建及 SHA-256；存在客户端改动时明确 native 渲染验收边界。相同坐标不重新发布不同字节，依赖下载精确锁定，不自动覆盖玩家旧 Jar。

代码仓、plan 与 Wiki 分开提交。多仓交付清单记录关联 PR 和各自状态，不做跨仓自动回滚或自动合并。公开 Wiki 遵守每 Mod 注册表的 local-source / published-release 边界，历史截图不改标成新版本。

## HUD 公共构件：后续候选（尚未实施）

用户补充的 GTMB 指定/自定义提示 HUD、模式切换，以及 GTSWN 轮盘和其他 HUD 已纳入候选。实读入口：GTMB HologramWorldGuide、HologramCutModeScreen、HologramCutInput.Switcher；GTSWN TerminalWheelGeometry、TerminalWheelHold、PortableHudLayout。

- 轮盘几何可参数化扇区数、起始角、顺逆时针、内外半径和间隙命中；现有八扇区、向上起始、顺时针和0.025间隙为消费者配置，绘制与命中共用同一几何。
- 提示框可提供测量/换行适配、锚点、边距、背景与逐行布局，并注入样式和避让区域；GTMB 的按键高亮、Waila 命中判断、RenderWitness 及 NBT 光标业务继续由消费侧决定。
- 不把输入协议强行合成一个状态机：GTMB 是 MUI2 模态屏，Shift 松开仅提交一次、右键切换、Esc 取消；GTSWN 是10tick长按确认、首次释放抑制、后续短按释放切换、Shift TAKE。可以共享中立输入工具，但保留各自手势语义、权限与网络操作。
- PortableHudLayout 的 EU/AE 分组、source 不可分分页和超高单元规则是业务策略，未来通过策略接口调用中立布局器，不直接搬运 PinnedLine 或把分页当作提示换行。

下批先选实际重复且有真实消费者的最小构件，核对屏幕缩放、隐藏条件、GUI抢占和状态所有权。验证聚焦纯几何边界、布局、消费者编译和必要显示/输入核验。已推送0.1.1及0.1.2不改写；0.1.3新增独立世界等距引擎并统一消费者依赖及补下载清单。HUD 候选不会因此被算作已完成。

## 集中测试约定

优先在一个隔离 GTNH 实例内同时加载全部消费者的精确 clean 候选与统一 Core 基线，记录源码、Tag、普通 Jar SHA 和运行参数。先做补下载、共同加载与依赖/类加载 smoke，再按实际变更运行少量业务场景；各仓继续拥有自己的维度、场景、权限与报告。集中启动成功不能替代 GUI、光效、输入或负载验收，避免在多个实例反复跑同一启动流程。客户端优先4 GiB，上限5 GiB。

0.1.1 已在 GTNH 2.9.0 RC-2、FalsePatternLib 1.12.2、4 GiB 专服中验证七份一致声明补下载一份 Core、共同启动、命令响应与正常停服。下载 SHA-256 与正式 Maven 普通 Jar 一致。未做物理客户端或完整玩法矩阵。

## RC2 集中回归增补

0.1.2 已固定 RC2 平台版本与下载器 bundled marker 的单一 RELEASE_VERSION 来源。消费者共同构建与集中专服加载已通过；本轮新增权限、假玩家登出、洗矿批量、跨总线输出、流体模式与 MUI2 空选择边界回归。完整原始结果及仍未覆盖项记录在私有 Wiki 的 plan/core-20261020，最终计数以归档 JSON 为准，不把历史 latest 文件或启动成功当作玩法全部通过。

## 0.1.3 独立世界等距引擎

Core 统一拥有镜头 lease、投影/反投影、输入抑制、渲染原点恢复及公共 early Mixin。Outpost 保留原公开门面与游戏模式、战斗和 Support 专属透视，移除公共 hook 副本。GTMB 只传姿态和策略，通过同帧世界射线执行原选点事务，不新增相机 Mixin。GUI 内蓝图预览引擎不变。详见 [相机 API](world-camera.md)。

消费者的按键、相机优先级和外观均是本地策略，不进入 Core 默认配置。已有0.1.x API 不删除，不自动升级玩家旧 JAR；新消费者需要0.1.3。0.1.2 集中筛查证据保留历史提交及产物 SHA，不能直接当作0.1.3 渲染验收。
