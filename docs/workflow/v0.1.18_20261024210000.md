## 修复机制

MixinEntityRenderer 从 @WrapMethod(renderWorld) 改为 @WrapOperation，目标是 updateCameraAndRender(F)V 内对 EntityRenderer.renderWorld(FJ)V 的 invoke。目标方法的限帧和不限帧分支都经过该调用点。保留原有 try/catch/finally 结构，只在 original.call 参数中增加 receiver。

新建的 runCameraRenderBoundaryContracts 实际调用编译后的生产 handler，并替换 Minecraft/GL 依赖。契约覆盖成功路径、begin/render/end 各自抛出 RuntimeException 与 Error、render/end 双异常时维持原有覆盖语义，以及参数传递。

## 静态兼容与 ABI 审计

对 Core、Angelica 2.2.28、Minecraft、GTIT、GTSWN、GTSR、GTMB 与 Outpost 做了调用审计，确认范围内没有绕过该调用点直接调用 renderWorld 的调用方。未知第三方直接调用者未纳入确认范围，不能据此宣称全模组无损。

ABI 对比覆盖所有类层级中的 public/protected JVM 声明：Core 0.1.10 的 148 个类、954 项声明，以及 Core 0.1.17 的 170 个类、1201 项声明均由候选保留。证据：build/verification/curvy-compat/abi-candidate.json。
