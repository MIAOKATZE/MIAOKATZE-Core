## 本轮文件与验证入口

README 推荐已分发的 `0.2.3`，将源码 `0.2.4` 明确标为候选；`gradle.properties` 的 `RELEASE_VERSION` 为 `0.2.4`。新增验证器为 `tools/verify-core-distribution.py`，对应测试为 `tools/tests/test_core_distribution.py`；隔离解析探针位于 `tools/distribution-probe`，CI 入口为 `.github/workflows/core-distribution.yml`。文件入口不代表执行或验收完成。

固定远端 0.2.3 的验证命令如下，输出目录由执行方指定：

```powershell
python tools/verify-core-distribution.py --mode remote --maven-root https://raw.githubusercontent.com/MIAOKATZE/MIAOKATZE-Core/7230dfe839af62e683aa9a8fde40cb31b13b36a5 --version 0.2.3 --source-sha 66d72c0b5c3f043d31dbd446308aa2e66f2039ba --output E:/CodeGT/.artifacts/core-v024/remote-023.json
```

本地制品使用 `--mode local --maven-root <本地 Maven 根目录> --version 0.2.4 --source-sha <最终候选完整 SHA> --source-root <Core Git 目录>`，根目录不是版本子目录。显式指定 `--source-root` 时，从本地 Git 对象读取该固定源提交的版本与选定源码；未指定时，从官方远端固定源 SHA 读取。两种来源由参数明确选择，不在失败时静默回退。固定提交对象检查不证明当前工作树干净。

JSON 回执记录 `status`、`coordinate`、`mavenRoot`、`sourceMode`、`source`、`files`、`jarChecks`、`moduleVariants` 和 `provenance`；检查失败返回非零退出码。它核对五项主制品、校验和、版本及元数据一致性和选定 sources 内容；不能由此推出全部二进制与源提交的构建溯源一致。

解析探针要求传入远端 `PASS` 回执，并预先将 `GRADLE_USER_HOME` 指向独立的新空目录；从 Core 根目录执行：

```powershell
.\gradlew.bat --no-daemon -p tools/distribution-probe verifyCoreResolution -PdistributionReceipt=E:/CodeGT/.artifacts/core-v024/remote-023.json -PresolutionReceipt=E:/CodeGT/.artifacts/core-v024/resolution-023.json
```

Linux 对应使用 `bash ./gradlew`。探针从回执读取精确坐标、Maven 根地址与哈希，专属仓库仅解析 Core group；分别以 `mcp`/dev 和 `srg`/normal 配置核对字节及 SHA-256，不使用 `mavenLocal()`、消费仓默认值或 Core 版本覆盖。CI 通过 `workflow_dispatch` 手动触发，默认固定上述已分发 0.2.3 的源 SHA 和 Maven 提交；本轮尚未触发远端 CI。

候选构建安排使用源仓外的 `E:/CodeGT/.artifacts/core-v024/`：`baseline.json` 保存基线，`build-clean.ps1` 驱动最终 clean Tag 的 `clean check assemble publishStableCoreLocal`，`publish-local.init.gradle` 复用显式版本发布逻辑，仅写本地 `maven-024` 目录。随后核验本地 `0.2.4` 与公开固定提交的 `0.2.3`；此处 `publishStableCoreLocal` 是本地制品准备，不是远端 Maven 发布。以上均为后续执行安排，结果尚待验证。
